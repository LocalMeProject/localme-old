# Audit — 2026-09-30

A full pass over the codebase and the GitHub repo (issues, branches, open PRs)
against the checked-in specification: `docs/LocalMe — Blueprint.md` and
`docs/LocalMe — Technical Documentation.md`. At the time of the audit `main`
was `f12de62` with no open pull requests and issues #1, #4, #5, #6, #7 closed,
so every finding below is a code-level gap between the spec and the
implementation.

Status: **all findings are fixed.** Each row names the change and the test that
now proves it. Gates at the end of the pass: `typecheck`, `lint`, `test` (SQLite
+ Postgres), `build`. A second pass closed the operational gaps the first one
left behind — they are listed in section F, with the decisions recorded in
[ADR 004](./adr/004-operational-hardening.md).

## How to read this

- **Spec** — the section of the contract the finding came from.
- **Was** — what the code actually did.
- **Now** — the fix, with the file that carries it.
- **Proven by** — the test that fails without the fix.

## C. Dialect parity

`db/sqlite/` and `db/postgres/` are statement-for-statement equivalent; the
Postgres tree now has migrations `001`–`007`. The dialect-neutral document-store
contract moved into `tests/db/document-store.contract.ts` and is executed by
**both** suites, so the two engines cannot drift: isolation, filters and every
operator (`$gt`, `$in`, `$exists`, `$and`/`$or`/`$nor`/`$not`), sorting,
pagination, `$set`/`$inc`/merge, the single-row cap, deletes, table listing and
identifier validation. The Postgres suite additionally asserts that the
`schema_migrations` ledger lists every file in `db/postgres/` and that
migration 003's columns exist.

`$nor` was added to the DSL in this pass (`lib/server/db/dsl.ts`) to complete
Mongo-style logical composition, and is asserted on both engines.

## D. Deliberate deviations

These are conscious choices, not gaps:

1. **Nine cron tasks, not five.** The five documented jobs plus
   `retry_failed_webhooks`, `storage_audit`, `heartbeat` and
   `renew_ssl_certificates`. The extra four are platform chores the Blueprint
   implies (retrying failed deliveries, auditing storage, keeping certificates
   alive) but never names. Documented in `/docs` and in
   `lib/server/cron-tasks.ts`.
2. **Compression on the wire, not in storage.** The Blueprint stores Brotli
   blobs; we store bytes verbatim (so backups, downloads and the editor stay
   byte-exact) and compress text responses instead. Same client-visible
   behaviour, no blob migration. Noted in `lib/server/compress.ts`.
3. **Flat system-config keys.** `system_configs` is key/value, so the §10 tree
   is stored as dotted keys and folded back into the documented nested shape for
   the API and the admin UI. Noted in `lib/server/system-config.ts`.
4. **Hotlink protection is on by default** and switchable with
   `serving.hotlink_protection`; §10 has no key for it, so the switch is an
   operator convenience rather than a spec field.
5. **Watermark text is fixed.** §14 fixes the attribution markup, so the
   per-project switch turns it off rather than editing it.
6. **Visit deduplication** uses a sliding window
   (`visits.dedupe_window_seconds`, default 300s) with visitor cookies that
   renew on each HTML page load.
7. **ACME is off by default and staging-first.** `ssl.auto_provision` is `false`
   and `ssl.acme_staging` is `true`, so the platform never contacts a public CA
   until an operator asks it to. See ADR 004.
8. **Webhook retries are off by default**, matching §5.9's "Retry: No
   retries". The outbox exists so a slow receiver cannot block the request that
   triggered the event; `webhooks.retry_failed` opts into a retry budget.
9. **The asset cache is in-process.** A single-node deployment gets the whole
   benefit; a scaled one would need a shared cache the spec never asked for.
   Correctness comes from invalidating on write, not from cache coherence.
10. **The console's own code editor is not Monaco** (§12.3), visitors are
    hashed with bcrypt(12) while accounts use scrypt, and the §14 watermark's
    label and link are operator config. Reasoning in
    [ADR 005](./adr/005-editor-hashing-and-watermark.md).

### G3. Configuration that did nothing

`storage.max_user_cap_bytes`, `storage.library_bonus_bytes`,
`cron.timeout_seconds` and `rate_limits.public_requests_per_minute` were all
declared in `SYSTEM_CONFIG_DEFAULTS` and read by nothing, while
`/docs` and the landing page described their behaviour as working. All four are
now wired — notably the library bonus, which is what makes the advertised "5 MB
of storage plus a 5 MB shared library" true; it was not.

> **Superseded 2026-10-01.** `storage.library_bonus_bytes` has been replaced by
> `storage.library_cap_bytes`, and the advertised allowance is now **2 MB of
> project files plus a 3 MB library** — two independent ceilings rather than a
> cap plus a bonus, which made the number impossible to state and impossible to
> lower without also lowering every project's budget. The finding above stands
> as written for 2026-09-30; this is the correction.

`retention.paid_log_retention_months` was **removed** instead: there is no tier
column and no billing, so there is nothing for it to apply to. An admin-editable
switch that does nothing is worse than an absent one.

The credential group's budget is now
`rate_limits.auth_requests_per_minute` (default 30) rather than a hardcoded
10. At 10, the `/auth/captcha` fetches that central rate limiting brought into
the group meant a user who hit `auth.max_login_attempts` (5) was 429'd on their
*successful* retry — a lockout with no way for the user to tell why.

### G4. Robustness and quality

- HTML is now compressed like every other text response; it previously bypassed
  negotiation entirely despite being the largest text payload a project serves.
- Compression moved off the synchronous zlib calls onto the thread pool.
- `putFile` performs its cap check inside the project write lock; two concurrent
  uploads could previously both pass it and overshoot the account cap.
- The webhook delivery `AbortController` timer is cleared on the failure path.
- Visitor bcrypt cost raised 10 → 12 per §7.3.
- Dead code removed: a pass-through `ownerUserId`, a `bodyPath` query fallback,
  and a `SELECT *` that pulled plaintext webhook secrets into memory.
- `/dashboard` and `/admin` are gated server-side; the operator console no longer
  renders its shell for non-admins.
- Dev servers apply the in-memory schema automatically, so `npm run dev` works
  from a clean checkout.

## H. Demo data

Request: populate the running instance with demo users. This found four defects
that no gate could catch, because there was no seeder to run.

| # | Finding | Fix |
| :-- | :------ | :-- |
| H1 | **`npm run db:migrate` and the server could open different databases.** The runner stripped the `file:/` prefix with its own regex instead of calling `resolveDriver`, so `DB_PATH=file:./data/localme.db` was rejected by the app (its schema requires `file:/`) but silently treated as a SQLite URI by the runner. | One implementation in `lib/server/db/sqlite-path.mjs`, imported by both.
